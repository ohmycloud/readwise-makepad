## 2026-10-01 — 增加 EPUB 局域网传书

- “导入 EPUB”增加方式选择：本机文件保留原有系统选择器，局域网传书显示临时接收网址与复制按钮。同一 Wi-Fi 下的电脑浏览器可批量选择 EPUB、查看上传进度及逐本导入结果；书籍实际入库后才返回成功，书架沿用现有刷新投影，传书不自动进入阅读页。Android 和桌面提供局域网入口；iOS 暂保留本机文件导入。

- 会话由 App 持有，关闭弹窗、退出书架和切到后台仍继续接收；再次打开保留网址与状态。“停止接收”、退出应用或开启后满 30 分钟才结束会话，下一次开启生成新网址。旋转及 LiveEdit/ScriptReapply 恢复弹窗、安全区尺寸、网址和状态，不重复启动服务。正文、注音、分页缓存及书架手势实现未改动。Android 增加应用内 dataSync 前台服务与对应普通权限，通知提供停止入口；服务销毁/超时直接设置 Rust 接收取消标志，不依赖已暂停的 UI 循环。会话 ID 隔离旧服务回调，避免影响新会话；Java 桥接和服务类纳入 APK 打包校验。传书会话持有限时 CPU 唤醒锁，停止/超时及服务销毁时释放。不增加存储或定位权限。另提供“允许后台接收”的系统授权入口，厂商省电设置由用户在系统中确认。设计依据：[Android dataSync 前台服务](https://developer.android.com/develop/background-work/services/fgs/service-types#data-sync)。

## 2026-08-28 — PortalList 空状态与缓存失效统一治理

## 2026-07-14 — M0 第八轮：iOS 构建失败根因——Homebrew Rust 劫持 rustc

- 症状：`rustup target add aarch64-apple-ios-sim` 已装、std rlib 齐全，但 run-sim 仍报 E0463 找不到 core/std。
- 定位：最小复现 + `rustup run stable sh -c 'which rustc'` → 解析到 `/opt/homebrew/bin/rustc`（Homebrew Rust 1.93.1）。机器上有两套 Rust：rustup 1.97.0 与 Homebrew 1.93.1，PATH 里 `/opt/homebrew/bin` 在 `~/.cargo/bin` 前。`rustup run stable cargo` 启动的是 rustup 的 cargo，但它按 PATH 找 `rustc` 时命中 Homebrew 版——它不认识 rustup 的 target 库目录 → E0463。
- 解决：卸载 Homebrew Rust（`brew uses --installed rust` 确认无包依赖它），或 PATH 里把 `~/.cargo/bin` 提到 homebrew 前。
- 教训：桌面构建一直"碰巧"能过是因为 host target 两套都有；交叉编译才暴露混用。
